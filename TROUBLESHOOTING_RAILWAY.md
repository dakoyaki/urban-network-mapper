# Railway Deployment Troubleshooting Guide

Common issues and solutions for deploying Urban Network Mapper to Railway.

## 🔍 Quick Diagnostics

### 1. Check Service Status

In Railway dashboard, each service shows:
- ✅ **Active** - Running successfully
- ⚠️ **Building** - Deploying (wait a few minutes)
- ❌ **Crashed** - Check logs immediately

---

## 🐛 Common Issues & Solutions

### Issue 1: Build Fails for Backend

**Symptoms:**
```
Error: failed to solve: process "/bin/sh -c pip install..." did not complete successfully
```

**Causes:**
1. GeoPandas/PostGIS dependencies failing to compile
2. Missing system libraries
3. Docker build context issues

**Solutions:**

**Solution A: Verify Docker Context**
```bash
# Check railway.json has correct paths
{
  "build": {
    "builder": "DOCKERFILE",
    "dockerfilePath": "backend/Dockerfile",
    "dockerContext": "backend"
  }
}
```

**Solution B: Test Docker Build Locally**
```bash
cd backend
docker build -t urban-mapper-test .
```
If this fails locally, the issue is with your code/Dockerfile, not Railway.

**Solution C: Use Nixpacks Instead**
In Railway dashboard:
1. Select backend service
2. Settings → Build Command
3. Clear the build command (leave empty)
4. Railway will auto-detect and use Dockerfile

---

### Issue 2: PostGIS Extension Errors

**Symptoms:**
```
ERROR: extension "postgis" does not exist
ERROR: extension "postgis_sfcgal" does not exist
```

**Solutions:**

**Solution A: Manually Enable Extensions**
1. Go to PostgreSQL service in Railway
2. Click **Query** tab
3. Run:
```sql
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS postgis_sfcgal;
```

**Solution B: Check Database URL**
In backend Variables, ensure:
```
DATABASE_URL=postgresql+psycopg2://postgres:PASSWORD@HOST:PORT/railway
```

Note the `postgresql+psycopg2://` prefix (not just `postgresql://`)

---

### Issue 3: Backend Crashes on Start

**Symptoms:**
```
[CRITICAL] Worker exited (pid: 12)
[ERROR] gunicorn failed to start
```

**Causes:**
1. Missing environment variables
2. Database connection fails
3. Import errors

**Solutions:**

**Solution A: Check Required Environment Variables**
Backend must have:
```bash
DATABASE_URL=<auto-generated by Railway>
SECRET_KEY=<any random string>
FLASK_ENV=production
CORS_ORIGINS=<your frontend URL or *>
DEFAULT_PROJECT_EPSG=3857
```

**Solution B: Check Logs for Specific Error**
```bash
# In Railway dashboard
Backend Service → View Logs → Look for Python traceback
```

Common errors:
- `ModuleNotFoundError: No module named 'xyz'` → Add to requirements.txt
- `sqlalchemy.exc.OperationalError` → Database connection issue
- `ImportError` → Check Python imports in code

**Solution C: Generate SECRET_KEY**
```bash
python -c "import secrets; print(secrets.token_hex(32))"
```
Use the output as your SECRET_KEY

---

### Issue 4: Frontend Can't Connect to Backend

**Symptoms:**
```
Failed to fetch
CORS policy blocked
Network error
```

**Solutions:**

**Solution A: Check API URL**
In frontend Variables:
```bash
VITE_API_BASE_URL=https://urban-mapper-backend-production.up.railway.app/api
```

⚠️ **Must use HTTPS, not HTTP**
⚠️ **Must include `/api` at the end**

**Solution B: Check Backend is Running**
1. Open backend URL in browser: `https://your-backend-url/api/projects`
2. Should see JSON response (not error)
3. If you see error, backend is the issue, not frontend

**Solution C: Fix CORS**
In backend Variables:
```bash
CORS_ORIGINS=https://your-frontend-url.up.railway.app
```

Or temporarily allow all (development only):
```bash
CORS_ORIGINS=*
```

### Issue 5: Frontend Build Fails

**Symptoms:**
```
npm ERR! Cannot find module 'xyz'
Build failed: Error: exited with code 1
```

**Solutions:**

**Solution A: Clear Build Cache**
In Railway dashboard:
1. Frontend service → Settings
2. Clear Build Cache
3. Redeploy

**Solution B: Check package.json**
Ensure all dependencies are listed in `frontend/package.json`

**Solution C: Use Correct Build Command**
In Railway frontend settings:
- **Build Command**: `npm install && npm run build`
- **Start Command**: Leave empty (static site)

### Issue 6: Database Connection Refused

**Symptoms:**
```
psycopg2.OperationalError: could not connect to server
Connection refused
```

**Solutions:**

**Solution A: Link Services Correctly**
1. In Railway project view
2. Ensure backend service and PostgreSQL are connected
3. Railway should auto-generate `DATABASE_URL`

**Solution B: Manually Set DATABASE_URL**
Get connection string from:
- PostgreSQL service → Variables → `POSTGRES_URL` or `DATABASE_URL`
- Copy the value
- Paste into backend service → Variables → `DATABASE_URL`

**Solution C: Check Database is Running**
1. PostgreSQL service status should be ✅ Active
2. If not, restart the service

---

### Issue 7: Port Binding Error

**Symptoms:**
```
Address already in use
Port 8000 is already allocated
```

**Solutions:**

Railway auto-handles ports. If you see this:

**Solution A: Use Environment Port**
Update `gunicorn.conf.py`:
```python
import os
bind = f"0.0.0.0:{os.getenv('PORT', '8000')}"
```

Or in `wsgi.py`:
```python
import os
if __name__ == "__main__":
    port = int(os.getenv("PORT", 8000))
    app.run(host="0.0.0.0", port=port)
```

Railway sets `PORT` automatically - don't hardcode it!

---

### Issue 8: Data Not Persisting

**Symptoms:**
- Can draw features
- Refresh page → data is gone

**Solutions:**

**Solution A: Check Database Tables**
1. PostgreSQL service → Query tab
2. Run: `SELECT * FROM project;`
3. If empty, tables weren't created

**Solution B: Create Tables Manually**
```sql
-- Run in PostgreSQL Query tab
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS postgis_sfcgal;

-- Tables should be created automatically
-- If not, check backend logs for initialization errors
```

**Solution C: Check Backend Logs**
Look for:
```
✓ PostGIS extension created
✓ Tables created
```

If missing, backend initialization failed.

---

### Issue 9: GeoPackage Export Fails

**Symptoms:**
```
Export failed: 500 Internal Server Error
```

**Solutions:**

**Solution A: Check GeoPandas is Installed**
Verify in `backend/requirements.txt`:
```
geopandas==1.0.1
```

**Solution B: Check System Libraries**
Verify `backend/Dockerfile` includes:
```dockerfile
RUN apt-get update && apt-get install -y \
    libgdal-dev \
    gdal-bin \
    ...
```

**Solution C: Check Logs**
Backend logs will show specific error:
- Missing library → Add to Dockerfile
- Permission error → Check file permissions
- Data error → Check geometry validity

## 📋 Step-by-Step Debugging Checklist

### Phase 1: Infrastructure

- [ ] Database service is running (✅ Active)
- [ ] Backend service is building successfully
- [ ] Frontend service is building successfully
- [ ] All services show "Active" status

### Phase 2: Configuration

**Backend:**
- [ ] `DATABASE_URL` is set (auto-generated by Railway)
- [ ] `SECRET_KEY` is set (any random string)
- [ ] `CORS_ORIGINS` includes frontend URL
- [ ] `FLASK_ENV=production`

**Frontend:**
- [ ] `VITE_API_BASE_URL` is correct (https://backend-url/api)
- [ ] `VITE_VWORLD_API_KEY` is set (if using Korean maps)

**Database:**
- [ ] PostGIS extension enabled
- [ ] SFCGAL extension enabled
- [ ] Tables exist (project, network_edge, network_node, source_polygon)

### Phase 3: Functionality

- [ ] Backend health check: `https://backend-url/api/projects` returns JSON
- [ ] Frontend loads without console errors
- [ ] Can draw sidewalk lines
- [ ] Data saves (draw → refresh → data persists)
- [ ] Export works (GeoPackage downloads and opens in QGIS)

## 🔧 Manual Fixes

### Reset Everything

If all else fails:

1. **Delete all services** in Railway project
2. **Keep only PostgreSQL** database
3. **Re-add services** from GitHub
4. **Wait for deployment**
5. **Configure environment variables**
6. **Test**

### Check Railway Status

Railway has status page:
- https://status.railway.app
- If Railway is down, wait for them to fix it

### Contact Railway Support

If Railway itself has issues:
- Dashboard → Help → Support
- Include deployment logs
- Describe your issue clearly

## 🎯 Common Configuration Mistakes

### ❌ Don't Do This:

```bash
# Wrong: Missing +psycopg2 in URL
DATABASE_URL=postgresql://...

# Wrong: HTTP instead of HTTPS
VITE_API_BASE_URL=http://backend-url/api

# Wrong: Missing /api
VITE_API_BASE_URL=https://backend-url

# Wrong: Hardcoded port
bind = "0.0.0.0:8000"  # Should use $PORT

# Wrong: Localhost in production
CORS_ORIGINS=http://localhost:5173
```

### ✅ Do This:

```bash
# Correct: Proper URL with driver
DATABASE_URL=postgresql+psycopg2://...

# Correct: HTTPS in production
VITE_API_BASE_URL=https://backend-url.up.railway.app/api

# Correct: Use PORT env var
bind = f"0.0.0.0:{os.getenv('PORT', '8000')}"

# Correct: Production domain
CORS_ORIGINS=https://frontend-url.up.railway.app
```
